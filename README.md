# WISHFLOW

### Make a wish. Let possibility find you.

**WISHFLOW** is a next-generation Web4 platform where people can share their wildest, most meaningful, ambitious, or unexpected wishes — and people with the ability to help can discover and make them happen.

We believe some ideas are too powerful to stay in someone's head.

Sometimes all it takes is one person saying:

> **“I can make that happen.”**

---

## 🌊 The Vision

WISHFLOW is building a new digital layer for **human generosity**.

Instead of asking people to search for traditional fundraising campaigns, WISHFLOW makes the **wish itself** the starting point.

A user can post a wish.

Someone else can discover it.

A benefactor can support it.

The wish can become reality.

And the fulfillment can inspire someone else to participate.

### The Flow

**Wish → Discover → Connect → Support → Fulfill → Inspire**

---

## 🚀 Why WISHFLOW?

The internet made information accessible.

Social media made attention accessible.

Crowdfunding made funding accessible.

**WISHFLOW explores what happens when we make generosity discoverable.**

People have millions of wishes every day:

* A student wants a laptop for school.
* An artist wants equipment to create.
* A creator wants to launch an ambitious project.
* A family dreams of an unforgettable experience.
* Someone wants to build something that helps their community.
* Someone simply has a wild dream they've never had the resources to pursue.

WISHFLOW gives those wishes somewhere to go.

# 🧠 MVP

The first version will focus on proving one simple question:

> **Will people post genuine wishes, and will other people actually want to make them happen?**

### Core MVP Features

#### 👤 User Profiles

Users can create profiles containing:

* Display name
* Username
* Profile picture
* Bio
* Location
* Wishes
* Fulfilled wishes
* Support history
* Reputation

---

#### ✨ Create a Wish

Users can create a wish with:

* Wish title
* Description
* Category
* Target amount
* Optional deadline
* Image/video
* Location
* Visibility
* Verification status

Example:

> **“I want to build a mobile recording studio for young artists in my community.”**

---

#### 🔎 Discover Wishes

A discovery feed allows supporters to explore wishes by:

* Trending
* New
* Most supported
* Almost fulfilled
* Verified
* Category
* Location
* Budget
* Impact

---

#### 💙 Support a Wish

A supporter can contribute toward a wish.

Possible MVP options:

* One-time contribution
* Partial contribution
* Full fulfillment
* Anonymous support
* Public support

---

#### ✅ Fulfillment

Once a wish has been fulfilled, the recipient can submit:

* Photos
* Videos
* Receipts
* Updates
* Thank-you message
* Proof of fulfillment

Fulfilled wishes become stories that can be discovered by the community.

---

# 🛡️ Trust & Safety

Trust will be one of WISHFLOW's most important product layers.

The platform should eventually include:

* Identity verification
* Wish verification
* Fraud detection
* Community reporting
* Benefactor protection
* Recipient reputation
* Fulfillment proof
* Transparent support history
* Anti-spam systems
* Moderation tools

**WISHFLOW should never become a marketplace for fake stories.**

Trust is the product.

---

# 🌐 Web4 Direction

WISHFLOW can begin as a traditional web application and gradually introduce Web4 infrastructure.

Potential future features include:

### Onchain Wishes

Allow users to optionally create onchain wish records.

### Crypto Support

Allow supporters to contribute using supported crypto assets.

### Wallet Profiles

Users can connect wallets and optionally associate them with their WISHFLOW identity.

### Onchain Fulfillment

Important milestones can be recorded onchain for transparency.

### Creator Coins

Creators and communities could eventually build ecosystems around recurring wishes and initiatives.

### Smart Contracts

Automated funding conditions could eventually allow contributions to be released when predefined fulfillment requirements are met.

### NFTs

Special fulfilled wishes could become collectible digital memories.

# 🔐 Security Principles

Security and trust should be designed into WISHFLOW from the beginning.

Never expose:

* Private keys
* Authentication secrets
* API secrets
* Payment credentials
* Sensitive user information

Environment variables should be stored securely and never committed to GitHub.

Example:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

Never commit `.env.local`.
